    Completed Work (condensed)

    - Benchmarking: `vectorforge/benchmark/` package (config, dataset, evaluator, writer, monitor, runner) plus CLI and helper scripts for runs, aggregation, plotting, and scale orchestration.

    Controlled experiments to run (design)
    -------------------------------------
    We will convert the quick observations into three formal experiments with controlled variables and repeat runs for stability.

    Experiment A — Exact vs HNSW
    - Goal: measure efficiency gained by ANN and its effect on retrieval quality.
    - Compare: `exact` vs `hnsw` (select representative `M` values).
    - Metrics: Recall@1/5/10, MRR, nDCG@10, p50/p95/p99 latencies, QPS, RSS, index-build time.
    - Key plot: Recall@10 vs p95 latency (each method/config as a point/curve).

    Experiment B — HNSW parameter sensitivity
    - Goal: quantify trade-offs for `M` and `ef_search` with other vars controlled.
    - Sweep example: `M ∈ {8,16,32}`, `ef_search ∈ {50,100,200}`, fixed `ef_construction` (or small grid).
    - Metrics: same as Experiment A. Produce heatmaps and Recall@10 vs p95 curves.

    Experiment C — Dense vs BM25 vs Hybrid
    - Goal: measure quality gains from combining lexical + dense retrieval and cost of fusion.
    - Configs: `bm25`, `dense` (exact or hnsw), `hybrid` with `alpha ∈ {0.25,0.5,0.75}`.
    - Metrics: Recall@10, MRR, nDCG@10, p95 latency, QPS. Plot quality vs latency.

    Scale dimension (10K / 50K / 100K)
    ---------------------------------
    - Run Experiments A–C at each scale to observe how exact and HNSW scaling behaviors differ (not just that larger = slower). Focus on how p95 and index-build time scale and how recall degrades or remains stable.

    Reproducibility & result schema (next engineering task)
    -----------------------------------------------------
    Every experiment artifact should include a compact provenance header. Proposed fields to store with each `experiment_id`:

     - `experiment_id`
     - `timestamp`
     - `git_commit`
     - `dataset` (path)
     - `dataset_hash` (e.g., sha256 of the .npz)
     - `query_set` (path + hash)
     - `embedding_model` (model name + weights sha/identifier)
     - `embedding_dimension`
     - `top_k`
     - `random_seed`
     - `method`
     - `M`, `ef_construction`, `ef_search` (when applicable)
     - `alpha` (hybrid)
     - `warmup_queries`, `measurement_queries`
     - `index_build_time_s`
     - `mean_latency_ms`, `p50_ms`, `p95_ms`, `p99_ms`
     - `QPS`
     - `RSS_bytes`

    Include `results/pip_freeze.txt` and a short `hardware.txt` (CPU model, RAM) alongside the JSON outputs.

    Reproducibility: how to re-run
    -----------------------------
    1. Generate test collection and queries:
         - `python -m vectorforge.scripts.generate_sample_collection`
    2. Install optional dependencies if desired:
         - `pip install psutil hnswlib` (Windows: prefer conda for `hnswlib` if build tools are missing)
    3. Run one of the orchestrators:
         - Baseline + sweeps: `python -m vectorforge.scripts.run_experiments`
         - Scale runs: `python -m vectorforge.scripts.scale_experiments`
    4. Aggregate & plot:
         - `python -m vectorforge.scripts.aggregate_results`
         - `python -m vectorforge.scripts.plot_results` (requires `pandas` and `matplotlib`)
    5. Capture environment:
         - `python -m pip freeze > results/pip_freeze.txt`
